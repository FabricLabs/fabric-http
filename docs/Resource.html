Class: Resource

Resource(name, definitionopt)

A Fabric HTTP Resource. A single `define()` call on FabricHTTPServer produces one Resource. The Resource owns its store, its schema, and every HTTP verb handler. Nothing outside this class needs to know about schema layout or pagination rules. ## Quick start ```js server.define('Message', { description: 'A chat message', properties: { content: { type: 'string', required: true, maxLength: 65536 }, conversation_id: { type: 'string', required: true, index: true }, role: { type: 'string', enum: ['user', 'assistant', 'system'] }, status: { type: 'string', enum: ['ready', 'computing'], default: 'ready' } }, auth: { read: false, write: true }, pagination: { default: 20, max: 100 }, sort: { field: 'created_at', order: 'desc' } }); ``` ## HTTP semantics | Verb | List path | Item path | |---------|----------------------|----------------------| | GET | Paginated list | Single item | | HEAD | Count + page headers | ETag + exists | | POST | Create (→ 303) | — | | PUT | — | Full replace | | PATCH | — | Merge-patch update | | DELETE | — | Remove (204) | | SEARCH | Body-driven filter | — | | OPTIONS | Full JSON-Schema | Schema + Allow | | META | Collection stats | Fabric item identity | ## Document market hooks Both are optional; without them the resource behaves as above. - `offers(record, req)` → provider offers for an item. The item GET then answers `{ document: record, offers }`. - `blobOffer(blobHashHex, req)` → payment settings for one blob (`documentOffer`, `amount`, …, merged over `settings.payments`), or nothing when that blob is not for sale. Blobs are content-addressed and may belong to many documents, so this mounts the canonical `GET /blobs/:hash` (`definition.routes.blob` to move it; it must keep a `:hash` parameter). That route answers HTTP 402 with `X-Fabric-Payment-Request`, or 404 when `blobOffer` returns nothing, 500 when the hook throws or returns an `amount` that is not a positive number, 503 when `settings.payments` is off or `server.bitcoin.createInvoice` is missing, and 502 when invoice creation fails or returns no usable invoice. A server mounts it only when no other route overlaps it.
