fallbacks on `Number.isFinite(created)`, but `Number(null)` and `Number('')` are a

`object.ts` fallback was skipped entirely, meaning a message carrying a valid ISO

collapse to this module when the pin exports the fix. Tests:
`tests/fabricPeeringChat.test.js` (non-positive → `now()`, `ts` fallback, positive

## Blockers before treating public Hub login as browser-grade auth
1. **Coordinated clients** — Hub SPA, site-login hosts, Passport, and GoonCitizen must use **prepare + commit** device-link (v2) and send `X-Fabric-Poll-Secret` from the create JSON. Do not put `pollSecret` on `fabric://` / QR / query strings.
2. **Device-link GET `linked`** — still Origin-gated so the responder (QR `sessionId` only) can read attestations without `pollSecret`.
3. **Origin-as-auth on the remaining read paths** — the single largest [#69](https://github.com/FabricLabs/fabric-http/pull/69) thread cluster (site-login completion, LiveRelay Bearer redeem, remote Hub self-sign, device-link redeem). The **write/redeem** paths are closed with `pollSecret`, but the pending/`linked` **GET** paths still treat a forgeable `Origin` as the gate because the QR responder holds nothing but `sessionId`. Closing it means giving the responder a real capability, which is a protocol change across Passport / GoonCitizen — **not** a quick win, and not fixable by adding more Origin checks. Do not mark those threads resolved until the responder carries a secret.
